**[English](community.md)** · **简体中文（当前）**

Semantica 以开放方式构建，汇聚了来自众多领域的研究人员、工程师和实践者的贡献。无论你是在提交 bug、分享项目，还是在审查 PR，你都是这个生态系统的一部分。


<a id="get-help"></a>
## 获取帮助

- [GitHub Issues](https://github.com/semantica-agi/semantica/issues) — 提交包含完整上下文的 bug 报告和功能请求。
- [GitHub Discussions](https://github.com/semantica-agi/semantica/discussions) — 提问、分享想法并讨论设计决策。
- [Pull Requests](https://github.com/semantica-agi/semantica/pulls) — 浏览开放的贡献并提交你自己的贡献。
- [Security Issues](https://github.com/semantica-agi/semantica/security/advisories/new) — 私下报告安全漏洞：切勿在公开 issue 中报告。


<a id="community-guidelines"></a>
## 社区准则

我们遵循 [Contributor Covenant 行为准则](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。本社区建立在四项原则之上：

- **尊重**：以友善和耐心对待每一个人，无论其经验水平如何
- **包容**：欢迎所有背景、领域和方法
- **协作**：共同致力于更好的解决方案，而不是在方法上相互竞争
- **学习**：公开分享知识、毫不犹豫地提问，并帮助他人成长

如要举报不可接受的行为，请提交一个带有 `[CoC]` 前缀的 GitHub issue。每份举报都会被调查。


<a id="ways-to-contribute"></a>
## 贡献方式

贡献的方式没有唯一正确的选择。请选择适合你技能和时间的方式：

### 代码

- 修复标记为 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 的开放 bug
- 添加新功能或集成
- 改进性能或重构现有模块

### 文档

- 修复拼写错误并提升指南的清晰度
- 为 API 参考文档添加示例
- 编写特定领域的 cookbook 笔记本

### 测试

- 为未测试的模块添加测试覆盖
- 复现并确认已报告的 bug
- 提升跨平台的测试可靠性

### 社区

- 在 issue 和讨论中回答问题
- 审查开放的 pull request
- 在 GitHub Discussions 中分享你的 Semantica 项目

详细的开发流程请参见[贡献指南](contributing-guide.zh-CN.md)。
